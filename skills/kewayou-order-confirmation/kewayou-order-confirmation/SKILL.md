# 客无忧订购确认单 Skill

## 目标

当用户提供营业执照图片，并给出手机号、订单编号/序号、总金额、软件/硬件要求时：

1. 从营业执照读取客户主体信息。
2. 按固定合同模板生成 `.docx`。
3. 校验软件、硬件与合计金额。
4. 软件默认按 `998元/年` 处理，除非用户明确指定其他价格或周期。
5. 默认软件服务从“确认日期的次日”开始，期限1年，结束日为下一年度对应开始日前1天。
6. 同时输出一条固定格式的微信确认话术。
7. 合同只保留“一、订购内容”“二、付款、开通与交付”“三、重点约定”三部分，不新增第四部分微信话术。

## 输入优先级

按以下优先级取值：

- 用户本轮明确输入 > 营业执照 > 既有模板默认值。
- 用户明确给出的订单编号必须原样使用，不自行改号。
- 用户只说“002”时，按确认日期拼成 `KWY－YYYYMMDD-WJ-002`。
- 未给序号且上下文也无法确定时，默认 `001`。
- 订单编号中 `KWY` 后的第一处分隔符使用全角 `－`，示例：`KWY－20260919-WJ-001`。

## 营业执照字段提取

必须从营业执照图片读取并核对：

- 客户全称：严格按“名称”字段，不缩写、不自行改字。
- 统一社会信用代码。
- 主体类型：公司/有限责任公司等，或个体工商户。
- 法定代表人/经营者姓名。
- 住所/经营场所（若合同模板需要）。

手机号通常由用户单独提供，不从营业执照猜测。

### 身份称谓

- 公司主体：使用“法定代表人”。
- 个体工商户：使用“经营者”。
- 若用户指定的确认人姓名与营业执照上的法定代表人/经营者不一致，不要把其写成法定代表人/经营者；应先提醒用户确认身份。

## 订购规则

### 软件

默认：

- 产品：`客无忧软件服务`
- 数量：`1`
- 服务期限：`1年`
- 金额：`998元`

只有用户明确要求时才修改软件价格或期限。不要再使用“买断”“终身”等旧表述。

### 服务日期

若确认日期为 `D`，用户没有另行指定开始时间：

- 开始日期 = `D + 1天`
- 结束日期 = 开始日期满1年后的前1天

示例：确认日期 2026-09-19，则服务期为 2026-09-20 至 2027-09-19。

### 硬件

- 硬件名称必须按用户提供的报价单、图片或文字列明。
- 多件硬件可合并为一个“硬件套装”描述，例如：`商米D2单屏收银机+商米扫码枪+小票打印机`。
- 若用户只给总额，未给硬件金额：`硬件金额 = 总额 - 软件金额`。
- 若用户明确给出硬件金额，则以用户给出的金额为准，并校验合计。
- 保修期限未明确时，不自行承诺新的保修年限；优先沿用用户明确提供的报价/模板信息，否则写“按厂家标准”。

### 合计校验

必须满足：

`订单总额 = 软件金额 + 硬件金额 + 接口/其他收费 - 优惠`

若用户只给软件，无硬件，则硬件行清空，合计等于软件金额。

金额大写必须与数字一致，例如：

- 998 → 玖佰玖拾捌元整
- 2500 → 贰仟伍佰元整
- 2740 → 贰仟柒佰肆拾元整
- 3000 → 叁仟元整

## 合同固定信息

除用户明确要求修改外：

- 供应方全称：`杭州腾纵科技有限公司`
- 销售联系人：`吴静`
- 付款方式：全款
- 交付方式：远程开通 + 线上培训
- 合同结构：只保留三部分，不新增第四部分。

## 微信确认话术

### 公司主体

必须使用这一句式，不拆成多段，不额外罗列软件、硬件或服务期限：

`本人{姓名}，为{客户全称}的法定代表人。本人已完整阅读并确认《客无忧产品及服务订购确认单》（编号：{订单编号}）全部内容，同意以本微信作为确认方式，并按照确认单约定订购，订单总金额为人民币{总金额}元。`

示例：

`本人汪敏昌，为上饶市秦通百货有限公司的法定代表人。本人已完整阅读并确认《客无忧产品及服务订购确认单》（编号：KWY－20260919-WJ-001）全部内容，同意以本微信作为确认方式，并按照确认单约定订购，订单总金额为人民币2500元。`

### 个体工商户

只将身份称谓改为“经营者”：

`本人{姓名}，为{客户全称}的经营者。本人已完整阅读并确认《客无忧产品及服务订购确认单》（编号：{订单编号}）全部内容，同意以本微信作为确认方式，并按照确认单约定订购，订单总金额为人民币{总金额}元。`

## 生成步骤

1. 读取营业执照图片，提取客户全称、统一社会信用代码、主体类型、法定代表人/经营者。
2. 读取用户给出的手机号、金额、订单号/序号、硬件内容。
3. 计算软件服务起止日期和硬件金额。
4. 先做字段校验：姓名身份、统一社会信用代码、软件金额、硬件金额、总额、服务期。
5. 使用 `references/base_template.docx` 和 `scripts/build_contract.py` 生成合同。
6. 使用 DOCX 渲染能力将生成的 DOCX 渲染成 PNG，逐页检查：无截断、重叠、乱码、金额错误、日期错误。
7. 如果版式异常，修复并重新渲染，直到通过。
8. 最终返回：
   - DOCX 下载文件；
   - 单独一条微信确认话术。

## 脚本调用

准备 JSON（参见 `examples/order.example.json`）后运行：

```bash
python scripts/build_contract.py \
  --template references/base_template.docx \
  --data examples/order.example.json \
  --out /mnt/data/客无忧产品及服务订购确认单.docx \
  --wechat-out /mnt/data/微信确认话术.txt
```

若运行环境没有此脚本所需依赖，可用 `python-docx` 直接编辑模板，但仍必须遵守上述字段和校验规则。
