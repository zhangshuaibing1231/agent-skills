# 周报数据规则

## JSON 结构

所有顶层字段都必须存在。没有内容的数组填 `[]`，不要填 `null`。

```json
{
  "author": "吴静",
  "period": {"start": "2026-09-14", "end": "2026-09-18"},
  "follow_up": [{"name": "客户名称", "type": "客户类型", "stage": "当前阶段", "progress": "本周进展", "next_action": "下周动作"}],
  "closed_won": [{"name": "客户名称", "type": "客户类型", "product": "购买产品", "key_reason": "关键促成点", "next_action": "待执行事项"}],
  "blocked": [{"name": "客户名称", "type": "客户类型", "blocker": "核心卡点原因", "next_action": "下周动作", "risk": "高"}],
  "lost": [{"name": "客户名称", "product": "原本意向产品", "reason": "流失真实原因", "review": "情况复盘"}],
  "skills": [{"scene": "具体场景", "technique": "可复用的销售技能或技巧"}],
  "faqs": [{"question": "客户常见问题", "concern": "客户真实关注点", "answer": "建议回答方式"}],
  "industry_info": ["本周观察到的价格、采购、产品或行业变化。"],
  "support": [{"issue": "需要公司支持的问题", "support_needed": "希望支持方式", "owner": "相关人或团队"}]
}
```

## 分类口径

### 跟进中客户

仍需销售推进的客户，包括需求沟通、合同确认、测试、报价、付款跟进、开票资料跟进和项目筹备。若客户本周已成交，但成交后仍有交付事项，主记录放在成交客户，交付动作写在“待执行事项”。

### 成交客户

仅收录来源中明确完成付款或收款的客户。小程序认证完成、确认单已制作、准备打款或发起交付本身不等于本周成交，除非上下文同时明确付款结果。

### 卡点客户

收录真正阻碍成交或实施的因素，例如价格模式不接受、产品功能不支持、接口能力缺失、关键资料未提供或客户长期无明确决策。不要把普通的下一步工作都写成卡点。

风险等级建议：

- 高：收费模式或核心功能不满足，可能直接导致不成交或影响品牌推广。
- 中：客户仍有意向，但预算、负责人、实施条件或方案尚未确认。
- 低：资料、开票或普通流程等待，可通过明确动作推进。

### 流失客户

只有明确在其他渠道下单、明确拒绝合作、项目取消或已更换系统时才算流失。没有明确流失时保持空数组，脚本会自动生成无流失说明。

## 去重与写法

- 以最新一天的状态覆盖早期状态。例如先“催打款”，后“已收款”，最终写成交。
- 同一客户可同时出现在“跟进中”和“卡点”中，但两处内容必须各有作用：前者写推进状态，后者写核心阻碍和风险。
- 客户名称、价格、产品版本和负责人沿用来源原文。对明显口误可做最小修正，但不要自行扩写。
- 每个单元格尽量用 1 至 2 句完整短句，避免把整段日报原样塞入表格。
- 下周动作必须具体，如“确认合同意见”“催收开票资料”“安排售后交付”，避免只写“持续跟进”。
